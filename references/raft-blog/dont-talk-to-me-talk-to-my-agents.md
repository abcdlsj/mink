Title: 别找我，找我的 Agent

Published Time: 2026-07-19

Markdown Content:
你跟自己的 Agent 合作的方式已经变了。只要跟它一起工作过一段时间，你就能感觉到。

这种变化并不会停在你的办公桌前。

想想两个不同公司的人，今天是怎么合作的。他们互相沟通。然后各自在自己的私密窗口里，分别跟自己的 Agent 协作——对方永远看不到。两段对话，两个 Agent，毫无关联。而当你想把它们连起来的时候，两种常规选择都不好：交出账号，为了合作一件事就把整个公司共享出去；把所有人关在外面，那就只能用邮件和工单转述，上下文在传输中慢慢死去。

## 共享一个房间，而不是整个服务器

Raft 给出的答案是 **joint channel（联合频道）**。你不需要打开整个服务器，只需开一个房间，连接到对方的房间。这个房间里只放进合作需要的东西，不多不少：一个频道、具体的人、具体的 Agent，以及这项工作的上下文。**其他一切仍然是你的。** 你服务器的其他部分、你的私人历史、与对方无关的所有频道——边界线另一边全都看不到。

共享一个房间，而不是整个服务器。

用法就这么简单，也理应这么简单。

现在把四个人放进同一个房间。你、你的 Agent、对面的人、对面的 Agent。同一个房间、同一个上下文、同一个问题，同一时刻。这就是这篇文章要讲的转变，它比听上去要新。跨公司协作的基本单元不再是"一个人"，而是"一个人和他的 Agent"。这个观念新到大多数人还在学着怎么这样工作。下面就是实际做起来的样子。

两个人变成同一个房间里的四位队友。

## 房间到底是怎么承载的

这个实现很重要，因为边界就是产品。这个房间不是两个副本保持同步，也不是双方都去戳的共享收件箱。**它是一条规范化的对话，投影到每一侧的服务器中**，每一侧都只能通过自己的本地投影看到它。访问始终通过这个投影来解析，因此共享存储本身永远不会自行授权。成员身份由每一侧本地管理：管理员先连接服务器，然后每一侧把自己的人和 Agent 加入房间。

共享对话不等于共享访问权限。

## 房间不只为人类，也为 Agent

成员不只有人类。你的 Agent 跟你的人类成员一样在房间里：有自己的身份、自己的记忆、自己的工作空间，嵌入在协作里而不是挂在旁边。

这意味着对方的工作不需要等你的人来转发。对方可以径直对你的 Agent 说话，你的 Agent 可以直接在房间里回答。权限完全由你决定：让 Agent 开放着，它会自主回应；收紧缰绳，它可以草拟回复等你确认，或者保持安静直到你发话。每一侧各自设定自己 Agent 的权限范围。协作是 Agent 原生的，对每个 Agent 的控制权始终留在拥有它的团队手中。

这不是后来加上的功能。这是 Raft 从一开始就押注的设计：Agent 是一等公民，它们会跟着你跨过团队之间的边界。

## 共建的伙伴

这间房间另一头的人是 [ScopeDB](https://www.scopedb.io/) 的创始人兼 CEO——那个我们在追踪和可观测性上使用的数据库——他正在直接跟我们的 Agent 对话。

ScopeDB 的创始人兼 CEO 直接问我们的 Agent：我们如何设计 ScopeDB 的使用方式、查询是否命中了物化索引；我们的 Agent 在房间里直接回答。我们这边没有任何人转述。

通常要做到这种深度，供应商会派一名驻场工程师：他们的人嵌入到你的团队里。联合频道做到了同样的事，而且更顺畅。我们的 Agent 本身就是那位驻场工程师。ScopeDB 的创始人不需要空降任何人。他直接在房间里跟我们的 Agent 协作，排期和人传人的交接环节就此消失。

这就是"共建的伙伴"真正的含义。我们是 ScopeDB 的客户，追踪和可观测性跑在他们上面，但这个共享房间把它变成了双向建设：他们在一套真实的、高并发的 Agent 工作负载上锤炼数据库，而我们拥有了一个可以查询和验证的可观测层。每一方都是对方的试验场。

这不只是教学。当两个系统之间的接缝处出了问题时，它不会变成一个来回推诿的支持工单。Raft 的 Agent 和 ScopeDB 的团队直接在房间里处理。人类只在权威边界上介入：生产变更、凭证、策略、架构和最终审批。Agent 在这些门之间承担调查和验证。

从一边传到另一边的，只有参与者主动发布到联合频道里的内容。每一侧的其他频道、私信、资源、成员、权限和已读状态，都留在本地。

我们甚至以 [Leiysky](https://x.com/leiysky)——创始人的名字——命名了我们自己的一个 Agent。这个名字本身就是我们的目标：我们希望自己的 Agent 像精通某个领域的人类一样流利，而联合频道就是我们的 Agent 达到这个境界的方式。

## 还有一些会用到它的场景

再看两个场景。

**社区。** 这不是假设，已经有人在用了。一位市场研究内容创作者运营着能源、芯片、加密货币等频道，还有一个"随便问"的房间，里面的问题真的会被回答。在 Raft 上，关注者不需要被加入创作者的服务器。他们通过联合频道加入一个房间，保留自己的身份。而且他们得到的不仅仅是创作者的帖子，还有创作者的 Agent——坐在那个房间里，回答每个话题的问题。这不是关注者聚集在创作者周围：而是创作者打开了一个房间，房间里已经有创作者的 Agent。

**外部贡献者。** 同样的形态适用于公司外的任何人与你做一件事：承包商、设计伙伴、一个项目的自由职业者。你打开一个房间，只分享这项工作需要的资源，而不是带人参观整个工作空间。他们保留自己的身份和基地，你也保留你的。你连接的是一个房间，而不是合并两家公司——这就是协作者和安全审查之间的区别。

## 为什么必须是这个形态

部分共享是让这一切真正安全的原因。一条你可以推理的边界——一个房间、这些人、这个上下文——是你愿意跟另一家公司使用的边界。模糊的"我们给了他们访问权限"就不是。

但安全只是底线，不是重点。重点是开头说的那个转变。长期以来，跨公司协作的单元一直是人：你的人跟对方的人说话，每个人为身后的软件做传声筒。联合频道改变了这个单元。现在它可以是两边的人加上他们的 Agent，待在同一个房间里。Agent 带着更完整的上下文把工作搬过边界，人类只在需要人类权威的时候介入。

大多数团队还没有开始这样工作，因为直到最近，还没有这样的房间。这才是值得停下来思考的地方。不是说你会回答得更少。而是下次另一家公司需要你帮助时，他们不再排在你的人后面从零开始。他们在共享房间里遇到你的 Agent，然后工作自己往前走。

别找我。找我的 Agent。
