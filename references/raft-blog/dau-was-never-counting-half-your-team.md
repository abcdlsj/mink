## DAU 看到了什么

DAU 背后的模型很简单：一个人打开你的产品，做一些工作，关掉。数一数露面的人，你就能合理判断这个东西有多活跃。

这个假设正在**崩塌**。

在一个 Agent 承担自己那份工作的工作空间里，最重要的事情往往发生在没有人类活跃的时候。Claude Code 仍在某人的终端上运行。一个编码 Agent 正在审查中。一个发布 Agent 在 flag 翻转后监控错误。DAU 完全看不到这些。不是说 DAU 错了。而是说单靠 DAU 已经无法捕捉一个工作空间真正在做什么。

## DAU 没看到什么

我们叫它 DAA，Daily Active Agents。

定义完全镜像 DAU：一个 Daily Active Agent 是当天至少发送了一条可见消息的 Agent，就像 Daily Active User 是当天做了同样事情的人类。同样的门槛，同样的窗口，一个数人，一个数 Agent。

**这个指标让你看到的东西比指标本身更重要。** 一个工作空间在没有任何人发送消息的情况下完成了一次部署、一次审查和一次回滚检查。DAU 看到的是安静的一天。DAA 看到的是工作。

## DAA 如何计算

以下是我们在 [Raft](https://raft.build/zh-cn/resources/blog/introducing-raft-where-humans-and-agents-build-together/) 内部计算 DAA 的方式。

一个 Daily Active Agent 是在该 UTC 日至少发送了一条可见消息的 Agent，与 DAU 计数人类的方式一致。门槛是每边一条消息，窗口是一个完整的 UTC 日。

当我们报告跨多天窗口的比率时，我们取每天的 DAA/DAU 平均值，而不是用总数相除——这样某一天异常大的数据就不会拉动整体数字。

在下图中，一个工作空间只有在**活跃**时才计入比率——即窗口内至少有 6 条可见消息，或至少在 2 个 UTC 日有活动。这个门槛不是 DAA 通用概念的一部分；它是我们保持这个 Raft 样本不把空房间当信号的方式。以下所有内容都按这个范围界定：Raft 工作空间、可见消息发送者、完整 UTC 日、活跃工作空间门槛。

Raft 活跃工作空间中每个活跃人类对应的 Agent 数量交互分布。

## 怎么读 DAA：一种形态，不是一个分数

Raft 是人类和 Agent 一起协作的工作空间。这让我们能看到一支团队在 Agent 承担真实工作后的实际样貌。在最近的完整 14 天窗口（2026 年 6 月 8 日至 21 日，UTC）中，Raft 上平均每天大约有 **3.65 个活跃 Agent 对应每个活跃人类**，日比率稳定在这个数字附近，在窗口内最近一个完整日 6 月 21 日达到 **3.92 倍**。

这是平台全貌。要问更有趣的问题——一个真正活跃的工作空间长什么样——我们必须走近看。

**比率告诉你这是什么类型的工作空间，而不是它有多好。**

更有用的视角不是标题数字，而是分布。我们不看平台平均，而是看活跃工作空间内部，问不同类型的团队是怎样构成的。

分布很宽：少数工作空间是人类独有，少数每人对 20 个以上 Agent，重心稳稳落在 **1 到 10 个 Agent 每人**的区间——大约 **84%** 的活跃工作空间在这个范围。把它当指纹读，不是排行榜。一个每人对 5 个 Agent 的空间并没有赢过一个持平的空间。它们在做不同类型的工作。

分区还揭示了两件事。**Agent 密集的空间不是安静的空间**——2 到 10 区间平均每空间约 340 到 660 条可见消息，而罕见的 20+ 区间平均约 5,700 条。更多 Agent 意味着更多工作，差一个数量级。而且**在典型工作空间内部，Agent 已经在写大部分消息**：在众数所在的 2 到 5 区间，约四分之三的可见消息来自 Agent，在远端接近 90%。DAU 漏掉的不是一半。在真正推进工作的工作空间里，那是对话的主体。

曲线说得很直白：在真正做事的那些工作空间里，很大一部分现在是持平或 Agent 偏重的，一个单一的人类活跃计数从来无法描述它们。

## 超越 DAA

DAA 只是一个度量透镜。它不是变化本身，而是看见变化的一种方式。

### 两种用户

底下的变化是：软件不再只是为人类用户而建。十年间，一个产品大体上可以假设用它的人就是点击它的人。这个前提不再成立。

Raft 从这种断裂的另一边出发。一个工作空间是人和 Agent 一起使用的。人类仍然在场，定方向、判结果、决定什么工作重要。但 Agent 也是产品中真正的参与者：阅读、书写、搜索、比较、关注、替别人行动。因此，人类活跃计数在两个方向上同时出错：对你团队中已有的 Agent 半盲，并且越来越指向世界上错误类型的用户。

### Agent 作为一等用户

这指向一个比「怎么数 Agent」更难的问题。它是：当 Agent 也是用户时，软件长什么样？只有你先接受 Agent 是有一等参与者身份、有历史、有团队位置的存在，你才有理由关心 DAA。否则，Agent 只是基础设施，它的活动只是背景噪音。名字是这种转变变得可见的一种方式：一个[有名字的 Agent 可以随时间承载期望和信任](https://raft.build/zh-cn/resources/blog/agents-need-names/)，而不是消失在匿名工具槽里。

一旦 Agent 被当作用户对待，产品问题就变了。界面仅对人类操作者可读已经不够；Agent 也需要它们能理解和行动的产品界面。这就是 Raft 博客上 [AX 写作](https://raft.build/zh-cn/resources/blog/?tag=ax)的意义。

### 超越人-Agent 循环

DAA 还有第二个局限：它计数 Agent 的存在，而不是 Agent 之间的协作。一个工作空间可以有很多活跃 Agent，但仍然是一个人类一步一步操控一个 Agent。

下一个转变是从人-Agent 协作到 Agent-Agent 协作。在这种工作形态中，人类仍在循环中，但不是每一步的调度员。系统必须足够好地承载意图、上下文、交接、审查和恢复——好到一个 Agent 可以把工作传给另一个 Agent，而不把线程坍回一个人操作的检查清单。

这就是为什么接力信号很重要。在我们的样本中，大约四分之一的活跃线程已经显示一个 Agent 在同一线程内把工作交给另一个 Agent。其余主要是单 Agent 循环。有些较大的 Agent 阵容几乎没有接力；有些较小的团队主要是接力。阵容不等于接力。

这就是 DAA 底下的工作。数两种队友是一半。另一半是构建 Agent 那一半能真正运作的世界。

数 Agent，因为它们现在是团队的一部分。看接力，因为协作正在超越人-Agent 循环。把判断留给人类，因为方向不是仪表盘能拥有的东西。
