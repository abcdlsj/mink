# Sumi 视觉与 AX 设计思考

创建：2026-08-05。本文件是设计迭代唯一的过程记录，随讨论更新。设计确定后只写入 `docs/UI_DESIGN.md`；本目录不存放零碎探索文件。

`design-lab/` 只保留两类内容：本文件（设计思考）和 `demo/`（可运行样本工具）。

## 目标

Sumi 要对外发布，必须有自己的设计。现有视觉是从最近出现的另一家产品借来的签名，需要重做；同时引入 AX（Agent Experience）作为产品差异点。

## 已确认的方向

1. 现有 UI 的舒适感很强，骨架保留，不推翻。
2. 像素头像保留（用户明确喜欢）。
3. 视觉签名（色板、字体、装饰形态）需要换成 Sumi 自己的；具体抄了哪家产品无法指认，按“签名识别”原则处理。
4. AX 纳入本轮设计：不只换皮，还要表达 Agent 的存在、活动与注意力。
5. 只做纯亮色模式；深色 ROI 低，不做。
6. 结构上如果有更符合 UX/AX 的提案，可以提出讨论，但先不擅自定案。
7. In Review 的 review 可以由 Agent 承担，取决于任务分工；不是只有 Human 复核。

## 现有 UI 舒适感的证据分析

基于真实 demo 的像素分布和计算样式（2026-08-05）：

- 大面积暖中性色：主内容 `#FFFFFF` + 导航 `#FFFAEF`，合计约占全屏 80%；彩色是信号点（rail 黄约 5%，accent 粉约 1%）。
- 控件是“物件”不是“平面”：2px ink 边框 + 2-4px 硬阴影，全部控件同一规则。
- 高密度精确排版：10px 元数据、大写、tabular numbers、统一 62px 头与 36px 控件基线。
- 趣味克制：像素印章有性格，但不干扰阅读。

结论：舒适感 = 温暖纸感基底 + 可触摸物件语言 + 高密度精确排版 + 克制趣味。这些是骨架。

## AI slop 教训

第一版提案（墨与纸 / Fraunces / 朱色 / 低饱和）是典型 AI slop：把文化词当概念，配 serif 字体和压饱和色板，没有产品依据，换产品名也能用。教训：

- 设计必须从产品事实出发，不从文化符号出发。
- 先分析现有 UI 为什么有效，再决定改什么。
- “换主题”不是“设计”。Sumi 的差异点应该在产品模型（Human 与 Agent 共处、持续协作）里找。

## “抄袭”的判定：风格运动 vs 产品签名

- Neo-brutalism 是公开设计运动，谁都能用；骨架层（暖纸、硬边、密度）可以保留。
- 需要替换的是“签名”：特定四色组合、字体组合（Space Grotesk + Space Mono）、像素脸的具体形态。
- 因为无法指认原产品，签名替换的标准是：去掉任何“一眼能联想到某产品”的具体组合，而不是推翻整个风格。

## AX 框架（本轮设计的立足点）

AX（Agent Experience）是面向 Agent 的体验设计。Sumi 的产品事实：

- Human 与 Agent 是平等的 Member。
- Agent 持续在线、可被打断、可转向。
- Task 跨 Run 持续；Run 有唯一 Focus；Agent 有注意力入口（Inbox）。
- Agent 的活动是 Server 事实，不是模型调用。

视觉上分三层：

1. UX（Human 侧）：输入、阅读、引导 Agent。现有骨架已经很好。
2. AX-in（Agent 侧）：协议与信息结构要让 Agent 的注意力模型可表达——Run、Focus、Yield、Inbox 的呈现不是日志，是 Agent 的工作状态。
3. AX-out（Human 感知 Agent）：Agent 的活动应是一条有节奏的“痕迹”（Task 时间线、Threads、Runs、Result 是一条连续线），而不是散落的徽章；Run 状态、Task 状态、Computer 可达性分开表达。

## 设计原则候选

1. 温暖优先于冷静。
2. 控件是物件，不是平面。
3. 彩色是信号，不是装饰。
4. 密度优先于留白。
5. Human 与 Agent 对称，但差异可见。

原则是后续每次迭代的判据，可以增删，不着急定稿。

## 迭代方式

- 不一次定死 token；先建立“原则 → 视觉词汇 → 组件演化清单 → 样本评审”的框架。
- demo 是评审通道：任何改动都能一键起 demo、看样本、截图对比。
- 每次“灵光一闪”落盘到 `process/explorations/`，组件化后可复用。
